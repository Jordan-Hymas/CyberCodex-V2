## Learn

### mv moves and renames

`mv SOURCE DESTINATION` moves a file. Unlike `cp`, nothing is left behind at the old name: it's the same file, now reached by a new path.

Linux has no separate rename command because renaming is just moving a file to a new name in the same directory.

```sh
mv draft.txt final.txt   # rename
ls
cat final.txt   # same contents, new name
```

### Moving into a directory

If the destination is an existing directory, `mv` puts the file inside it and keeps its name. You can also move and rename in one step by giving the full new path.

```sh
mv final.txt reports
ls reports
mv reports/final.txt reports/2026-final.txt   # rename inside the folder
ls reports
```

### Check your work

After a move, the old name is gone. A quick `ls` confirms the file is where you expect and the old name has disappeared.

Be careful on a full Linux system: if a file already exists at the destination, `mv` replaces it without asking. The old contents are lost.

## Command cheat sheet

- `mv OLD NEW`: Rename OLD to NEW.
- `mv FILE DIR`: Move FILE into DIR, keeping its name.
- `mv FILE DIR/NEWNAME`: Move and rename in one step.

## New words

- **Rename**: in Linux, moving a file to a new name. It's the same operation as moving.

## Why it matters

Renaming files is everyday admin work, and knowing the difference between moving and copying avoids lost or duplicated data.
