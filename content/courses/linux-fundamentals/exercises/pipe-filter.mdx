## Learn

A pipe | sends one command's output into the next command. You can chain filters: grep DELIVER keeps matching lines, and grep -v TEST throws away lines containing TEST.

Each command in a pipeline does one small job. Chaining them lets you narrow output step by step without creating temporary files. Read your output after each step and add a filter only when you need one.

## Example

```sh
cat app.log | grep ERROR             # keep errors
cat app.log | grep ERROR | grep -v debug   # ...but drop debug lines
```

Example filenames illustrate syntax; inspect your mission files before running them.

## Your mission

stream.log contains several DELIVER lines, but only one is a live delivery. The others are TEST deliveries. Use a pipeline to isolate the live one.

1. Pipe stream.log into grep to keep DELIVER lines.
2. Add a second filter that removes TEST lines.

## Common mistake

Do not add a filename to the receiving command unless you intend it to read that file instead of the pipe.
