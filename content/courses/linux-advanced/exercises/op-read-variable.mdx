## Learn

### read stores a line in a variable

`read NAME` takes one line of input and stores it in the variable NAME. Combine it with `&lt;` and the input comes from a file: one step, no copying and pasting.

```sh
read VERSION < version.txt
echo "Running version $VERSION"
```

### Several variables at once

Give `read` several names and it splits the line at spaces: the first word goes into the first variable, and so on. The last variable gets whatever is left over.

```sh
read USERNAME PASSWORD < creds.txt
echo $USERNAME
```

### The pipeline trap

`cat version.txt | read V` looks reasonable but leaves `V` empty. Each stage of a pipeline runs in its own copy of the shell (a subshell), so the variable is set in that copy and disappears when the line finishes. Use `&lt; FILE` instead.

```sh
cat version.txt | read V
echo "[$V]"
```

### Why one step matters

Some values change constantly: rotating keys, temporary tokens, files another program keeps rewriting. Reading with `cat` and then typing the value takes two steps, and the value may already be stale. `read NAME &lt; FILE` captures it in a single command.

## Command cheat sheet

- `read NAME < FILE`: Store the first line of FILE in NAME.
- `read A B < FILE`: Split the line into words: A gets the first, B the rest.

## New words

- **Subshell**: a separate copy of the shell. Variables set inside it vanish when it ends.

## Why it matters

Scripts read configuration values and tokens this way all the time. It is one step, starts no extra program, and avoids the subshell trap.
