## Learn

### Redirecting stream 2

Put the stream's number in front of `&gt;` to redirect that stream. `2&gt; errors.log` sends standard error into `errors.log`. Write the `2` and the `&gt;` with no space between them.

```sh
netscan 2> status.log   # the result still shows; the message went to the file
cat status.log
```

### Both at once

One command can redirect both streams, each to its own file. Results go one way and messages the other, and nothing appears on screen.

```sh
netscan > results.txt 2> status.log
cat results.txt
cat status.log
```

### Throwing output away

`/dev/null` is a special file that discards everything written to it. `2&gt; /dev/null` silences error messages, which is handy for noisy commands. Use it carefully: you won't see real problems either.

```sh
netscan 2> /dev/null
```

### The spacing trap

`2 &gt; file` (with a space) is different: the shell treats `2` as an ordinary argument to the program and redirects standard output. The number must touch the `&gt;`.

## Command cheat sheet

- `COMMAND 2> FILE`: Save standard error in FILE.
- `COMMAND > OUT 2> ERR`: Split the two streams into two files.
- `COMMAND 2> /dev/null`: Discard error messages.

## Why it matters

Separating errors from results keeps logs clean and makes failures stand out instead of scrolling past.
