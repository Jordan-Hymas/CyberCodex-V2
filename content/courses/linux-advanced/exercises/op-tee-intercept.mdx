## Learn

### Pipelines hide what's in between

When `A | B` goes wrong, you only see B's complaint. What did A actually send? The data passed through the pipe and vanished. You need a way to look inside without breaking the pipeline.

### tee as a tap

`tee FILE` copies everything flowing through it into FILE and passes it on unchanged. Put it between two commands and you get a recording of exactly what crossed the pipe.

```sh
cat raw.txt | tee middle.txt | grep a | wc -l
cat middle.txt   # what flowed between cat and grep
```

### Debug, then fix

- Insert `tee FILE` between the two commands.
- Run the pipeline and read FILE: that's what the first command really sent.
- Change the first command based on what you learned, and run the pipeline again without `tee`.

## Command cheat sheet

- `A | tee FILE | B`: Record what A sends to B, without changing it.

## Why it matters

Debugging data flows is half of practical shell work, and tee is also how you watch a long command while keeping its output as evidence.

## Common mistake

emitter | tee /tmp/sent.txt on its own shows you the message, but receiver never gets anything. tee goes between the two commands, not in place of receiver.
