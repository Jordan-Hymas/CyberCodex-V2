## Learn

### How the shell finds commands

When you type a bare name like `ls`, the shell searches the directories listed in the `PATH` variable, in order, and runs the first match. Your PATH is printed below. Notice what's missing: your current directory.

```sh
echo $PATH
```

### Why the current directory isn't searched

This is deliberate, and it's a security feature. Imagine an attacker leaves a file called `ls` in a shared folder. If the shell searched the current directory, then the moment you walked into that folder and typed `ls`, you'd run the attacker's program instead of the real one. Keeping `.` off the PATH prevents that.

### Saying 'this directory' with ./

To run a program that sits in your current directory, you have to say so explicitly with `./`. The single dot means this directory, so `./scanner` reads as: the file called scanner, right here. That's a relative path, so it only works from the directory the program is in.

```sh
cd /opt/tools/bin
ls
scanner   # a bare name: not searched for here
./scanner   # explicitly this directory: runs
```

### Three ways to run the same program

- `/opt/tools/bin/scanner`: absolute path, works anywhere.
- `./scanner`: relative to the current directory, works only from `/opt/tools/bin`.
- `bin/scanner`: relative, works from `/opt/tools`.

```sh
cd /opt/tools
bin/scanner
```

## Command cheat sheet

- `./PROGRAM`: Run PROGRAM in the current directory.
- `echo $PATH`: Show where the shell looks for bare command names.

## Why it matters

Tools you download or build usually live in a working folder and are started with ./. Knowing why the dot is needed also explains a classic attack: if . is on PATH, a planted program can hijack an ordinary command.
