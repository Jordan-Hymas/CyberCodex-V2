## Learn

### Every process has a working directory

When you start a program, it begins life in your shell's current directory. That's its working directory. The program can check it, and it uses it whenever it opens a file by a relative name. That's why the same program can behave differently depending on where you run it from.

### Watch the working directory change

Our practice program prints the working directory it was started in. We call it by the same absolute path each time, from different places.

```sh
/opt/tools/bin/scanner
cd /var/log
/opt/tools/bin/scanner   # same program, different working directory
```

### Separate where you are from how you call it

Two different things are going on, and it helps to keep them apart. Where you stand is set with `cd` and shown by `pwd`. How you call the program (absolute or relative path) is about finding the file. With an absolute path you can stand anywhere and still reach the program.

This mission's program tells you where it insists on running, and that place is different for every learner. Read its message, move there, and call it again.

## Command cheat sheet

- `cd DIR then /path/to/program`: Run a program with DIR as its working directory.
- `pwd`: Confirm where you are before running it.

## Why it matters

Scripts and services often behave differently depending on the directory they start in, and relative paths inside them break when they start somewhere else. Checking the working directory is a standard first move when a tool works for one person and not another.
