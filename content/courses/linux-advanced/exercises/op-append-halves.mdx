## Learn

### &gt; truncates before the command runs

Here's a detail that catches people out: the shell empties the target file for `&gt;` before the command even starts. Whatever was in the file is gone the moment you press Enter, even if the command then fails or prints nothing.

```sh
cat audit.log
ls /nope > audit.log   # the command failed...
cat audit.log   # ...but the file was already emptied
```

### &gt;&gt; appends

`&gt;&gt;` opens the file for appending: existing content stays, and new output goes after it. If the file doesn't exist yet, `&gt;&gt;` creates it.

```sh
echo "10:00 check one" >> audit.log
echo "10:05 check two" >> audit.log
cat audit.log
```

### When a program and the shell both write

This mission's program writes part of its result straight into the file itself and prints the rest. With `&gt;&gt;` both parts end up together. With `&gt;` the shell's write lands on top of the program's. Picking the right operator is the whole mission.

## Command cheat sheet

- `COMMAND >> FILE`: Append output to FILE.
- `COMMAND > FILE`: Empty FILE first, then write the output.

## Why it matters

One wrong character between &gt; and &gt;&gt; is the difference between adding a line to an audit log and wiping it.
